SchemaForge V4 - R7.10 Db2 LUW P4.1 Sequence Default Fix

Problem found by first live Db2 LUW acceptance run:
  SQLCODE=-104 / SQLSTATE=42601 on
  WITH DEFAULT NEXT VALUE FOR <schema>.<sequence>

Db2 LUW does not permit a sequence NEXT VALUE expression as a column DEFAULT.

Fix policy:
1. Non-identity column with source <sequence>.NEXTVAL default:
   - never emit invalid WITH DEFAULT NEXT VALUE FOR syntax;
   - keep CREATE SEQUENCE;
   - place an inline DBA review warning in the SQL;
   - tell DBA/application to use NEXT VALUE FOR explicitly in DML or add a reviewed BEFORE INSERT trigger.
2. Logical IDENTITY column that also carries a legacy sequence NEXTVAL default:
   - render native GENERATED BY DEFAULT AS IDENTITY;
   - never emit sequence NEXTVAL as the column DEFAULT;
   - keep the canonical sequence object emitted separately (no silent canonical object deletion).
3. Live acceptance additionally executes VALUES NEXT VALUE FOR against the generated sequence.

No Docker/JDBC/environment change is required.
