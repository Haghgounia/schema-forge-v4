# R11.4.2 Legacy default and artifact-outcome hardening

## Trigger

A real Legacy Word REST package (`schemaforge-legacy-word-output_20260901_092236_337.zip`) showed two explicit source defaults recorded as recovery drops:

- `LEGALCOSTAMOUNT`: `Value = 0`
- `ALLOWEDDAY`: `Value = 0`

The canonical model therefore lost the explicit zero defaults even though the source evidence was unambiguous. The same package also showed `recoveryWarningCount=2` without the recovery findings appearing in generated SQL, and SKIPPED manifest entries had no per-artifact reason.

## R11.4.2 corrections

### 1. Explicit Legacy `Value = ...` defaults are preserved

`LegacyDefaultValueNormalizer` now recognizes the English legacy label `Value` only when it is followed by `=` or `:`. Examples:

- `Value = 0` -> `0`
- `VALUE: 0` -> `0`
- `Value=20` -> `20`

This is evidence-preserving normalization, not inference. The numeric/string/type compatibility checks still run after label removal, so unsafe or incompatible expressions continue to fail closed.

### 2. Recovery findings are visible in generated SQL

`SqlIssueCatalog` now promotes these parser findings into the normal DDL issue stream:

- `LEGACY_DEFAULT_DROPPED` -> WARNING / inline `DEFAULT-DROP`
- `LEGACY_DEFAULT_NORMALIZED` -> INFO / inline `DEFAULT-NORM`

Therefore a DBA can see default recovery decisions directly in each generated SQL script as well as in canonical metadata.

### 3. SKIPPED artifacts carry a manifest outcome reason

`ArtifactDescriptor` and manifest artifact entries now expose optional `outcomeReason` metadata. Metadata-dependent producers record deterministic reasons such as:

- `METADATA_UNAVAILABLE`
- `LIVE_SCHEMA_NOT_FOUND`
- `LIVE_TABLE_NOT_FOUND`
- `LIVE_TABLE_NO_PRIMARY_KEY`
- `DOCUMENT_NO_PRIMARY_KEY`
- `NO_SCHEMA_DIFF`

The field is additive under the current pre-freeze `schemaforge-manifest/v1` / Artifact Contract `1`; no generated artifact path, checksum, status, or package membership rule changes.

## Safety and scope

- No datatype, precision, key, or default value is guessed.
- DB2 z/OS deferred items remain deferred: bare `WITH DEFAULT`, `FOR BIT DATA`, enforcing-index source-name reuse, and live execution.
- Oracle, PostgreSQL, DB2 LUW, SQL Server, and MySQL closure baselines are not reopened.
- Existing DDL dialect behavior is unchanged except where an explicit Legacy source default was previously dropped and is now preserved.

## Regression coverage

Updated/added assertions cover:

- `Value = 0` / `VALUE: 0` / `Value=20` normalization;
- recovery findings in DDL header and inline column comments;
- manifest serialization of `outcomeReason` for SKIPPED entries;
- precise skip reasons in comparison, migration, and CRUD producers.
