# M10.3 — MariaDB dependency-closed safe cohort

## Purpose

M10.2 proved that the 2,058 M10.1 auto-selected tables are not yet a closed deployable schema:
review-table dependencies, missing legacy targets, canonical FK defects, and MariaDB mapping
exceptions remain. M10.3 does **not** repair, drop, or rewrite any of those semantics.

Instead it derives a deterministic deployment-pilot cohort by exclusion only:

1. load exactly the M10.1 auto-selected snapshots;
2. exclude tables whose local MariaDB DDL cannot be rendered safely;
3. run `ForeignKeyAnalyzer` on the remaining set;
4. remove only owner tables that still have blocking physical-FK errors;
5. repeat until the remaining set is dependency-closed and FK-deployable;
6. render one integrated MariaDB SQL script for the closed cohort.

Every excluded table is recorded with the iteration, blocker code, referenced table(s), and
evidence message. No FK, datatype, table name, or historical winner is guessed.

## Scope boundary

The result is a **persistent deployment pilot cohort**, not the final reconciled Legacy schema.
The final schema still requires explicit resolution of M10.1 review tables, missing legacy targets,
canonical FK defects, and MariaDB mapping exceptions.

## Runner

`CanonicalJsonMariaDbClosedSubsetIT`

Required inputs:

- `schemaforge.m10.mariadb.inputDir`
- `schemaforge.m10.mariadb.autoSelected`
- `schemaforge.m10.mariadb.manifest`

Output control:

- `schemaforge.m10.mariadb.closedSubsetOutputDir`
- `schemaforge.m10.mariadb.closedSubsetCleanOutput`
- `schemaforge.m10.mariadb.closedSubsetFailOnInvariant`

## Success contract

- selection contract mismatches = 0;
- final FK error count = 0;
- final `ForeignKeyAnalysisResult.deployable()` = true;
- integrated MariaDB rendering succeeds;
- MariaDB sanity checker accepts the emitted script.

The resulting SQL is suitable for the next live persistent-deployment pilot gate.
