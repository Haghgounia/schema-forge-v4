# M10.2 MariaDB Integrated Readiness Gate

## Purpose

M10.2 consumes the no-guess M10.1 selection artifacts and determines whether the 2,058 automatically selected logical tables form a deployable integrated MariaDB schema.

The gate is intentionally offline. It does not connect to MariaDB and it never removes or rewrites foreign keys merely because a referenced table is still in the M10.1 `REQUIRES_REVIEW` cohort.

## Inputs

- canonical JSON root
- `selection-auto-selected_*.csv`
- `selection-manifest_*.csv`

## Contract

1. Every auto-selected row must exist in the full M10.1 manifest with the same status and selected snapshot.
2. Every selected snapshot must exist and must contain the exact qualified table named in the selection row.
3. The integrated cohort must contain one and only one definition per qualified table.
4. Missing FK targets are classified as:
   - `REVIEW_DEPENDENCY` when the referenced table is present in the M10.1 manifest with `REQUIRES_REVIEW`.
   - `UNEXPECTED_MISSING_TARGET` when the target does not exist in the M10.1 manifest at all.
   - `MISSING_SELECTED_TARGET` for any internal selection-contract anomaly.
5. Each selected table is rendered independently through the MariaDB dialect using the full selected schema as type-mapping context and is checked by `MariaDbDdlSanityChecker`.
6. A complete integrated SQL script is emitted only when selection contract mismatches, FK blockers, and MariaDB render failures are all zero.

## Outputs

- `m10.2-mariadb-readiness-summary_<timestamp>.txt`
- `m10.2-mariadb-fk-issues_<timestamp>.csv`
- `m10.2-mariadb-render-failures_<timestamp>.csv`
- `m10.2-mariadb-contract-mismatches_<timestamp>.csv`
- `m10.2-mariadb-selected_<timestamp>.csv`
- `mariadb/integrated-auto-selected.mariadb.sql`

When the cohort is not fully deployable, the SQL file contains only a non-executable explanation marker. SchemaForge does not silently drop unresolved foreign keys.

## Exit interpretation

`BUILD SUCCESS` means the M10.1 selection contract was consumed consistently. It does not by itself mean the cohort is fully deployable. The decisive field is:

`Full integrated ready : true|false`

If false, the readiness reports identify the exact blockers for the next M10 step.
