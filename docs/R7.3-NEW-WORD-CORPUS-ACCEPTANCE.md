## R7.3.1 fail-closed rule

`MISSING_DATA_TYPE` is a diagnostic sentinel, not an executable database type. R7.3.1 makes it an invalid canonical model condition and `DdlGenerator` refuses to render it for every dialect.

This intentionally reduces apparent generation coverage for Oracle/PostgreSQL/Db2/SQL Server by the same three malformed source documents, replacing false-green invalid SQL with explicit failures.

## R7.3.3 strict regression gate

R7.3.3 adds an optional exact regression gate to `WordDirectoryMultiDatabaseGenerationIT`. It does not change parser or DDL generation semantics.

Enable with:

`schemaforge.word.failOnRegression=true`

Strict mode requires these properties:

- `schemaforge.word.expectedDocuments`
- `schemaforge.word.expectedSkipped`
- `schemaforge.word.expectedParseFailures`
- `schemaforge.word.expectedGenerated.<platform>`
- `schemaforge.word.expectedWithIssues.<platform>`
- `schemaforge.word.expectedFailed.<platform>`
- `schemaforge.word.expectedFailureCodes.<platform>` using `CODE:COUNT` entries separated by commas

The gate checks exact corpus size, skipped and parse-failure counts, exact per-platform generated/with-issues/failed counts, per-platform corpus accounting, and exact failure-code counts. Any unknown code or count drift fails the test.

The runner summary also records the configured numeric mapping strategy so SAFE and OPTIMIZED evidence is explicit in the report.
