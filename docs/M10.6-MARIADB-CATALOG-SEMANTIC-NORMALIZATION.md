# M10.6 - MariaDB catalog semantic normalization

M10.5 proved that the M10.4 persistent pilot deployment created all 1,907 expected tables. The live catalog contained exactly the expected 28,673 columns, 1,583 primary keys, and 19 foreign keys, with no missing expected tables. The remaining 1,354 residual changes were catalog/rendering round-trip representation differences.

The M10.6 correction is intentionally limited to `SchemaDiffEngine` semantic comparison:

1. MariaDB PRIMARY KEY columns are effectively NOT NULL even when a historical canonical column flag says nullable. This is treated as equivalent only for columns participating in the desired primary key.
2. MariaDB catalog numeric default formatting is normalized semantically. Numeric values that compare equal remain equal after catalog formatting, while quoted character defaults remain string-sensitive unless the desired SQL expression itself is an unquoted numeric literal or the desired column is numeric.
3. MariaDB automatic FK supporting indexes are treated as implementation artifacts when their name and key columns are exactly the live FK name/key columns.
4. MariaDB may surface `CREATE UNIQUE INDEX` through `INFORMATION_SCHEMA.TABLE_CONSTRAINTS` as a UNIQUE object. A desired standalone unique index with the same physical/logical name and key columns is treated as the same uniqueness object.
5. SchemaForge's MariaDB VARCHAR row-size adaptation can emit inline `CHECK (CHAR_LENGTH(...) <= n)` while the canonical model intentionally remains VARCHAR(n). The generated check is included in the effective desired comparison so it is not reported as an unexpected live constraint.
6. The diff engine now mirrors the DDL generator's duplicate index-key-column elimination and recomputes the emitted logical index name before comparison.

This is a convergence normalization only. It does not modify the database and does not weaken the No-Guess / No-Lossy contracts.

Expected M10.5 outcome after applying M10.6 to the existing persistent database:

- Missing expected tables: 0
- Residual column changes: 0
- Residual object changes: 0
- Residual changes total: 0
- Cohort converged: true

`Exact database converged` may remain false while the shared `TSTSHMA` database contains the 748 extra tables from earlier test/deployment runs. Those are table-set scope, not residual drift in the 1,907-table cohort.
