# Phase 19.3 - Distribution Assembly and Final Smoke

Status: release-engineering hardening in progress.

## Reproducible GA binary gate

The original GA artifact was validated and recorded with historical SHA-256:

`78057619993e942f0a43fb799da754b95282f365b4f6bab09210c86233f6db57`

A later clean rebuild produced different archive bytes although Production Java had not changed. The build therefore required reproducibility hardening before the distribution could be frozen.

The Maven build now defines:

`project.build.outputTimestamp = 2026-09-02T00:00:00Z`

`distribution\scripts\reproducible-ga-build-windows.cmd` performs two independent clean package builds with tests skipped, compares the two JAR SHA-256 values, and writes `distribution\checksums\SHA256SUMS.txt` only when both are byte-for-byte identical.

The full regression suite must be run separately before this reproducibility gate.

## Assembly

`distribution\scripts\assemble-distribution-windows.cmd` reads the frozen checksum from `distribution\checksums\SHA256SUMS.txt`. It refuses to assemble if `target\schema-forge-v4-4.0.0.jar` does not exactly match the frozen value.

Successful assembly creates:

- `target\schemaforge-v4-4.0.0-distribution.zip`
- `target\schemaforge-v4-4.0.0-distribution.zip.sha256`
- staged runtime tree under `target\distribution-stage\schemaforge-v4-4.0.0`

## Verification

Run from the project root:

`distribution\scripts\verify-distribution-windows.cmd`

The verifier checks the staged runtime layout, the staged GA JAR checksum, and the final ZIP checksum.

Runtime smoke remains:

`script\smoke-test-windows.cmd` inside the extracted distribution.
