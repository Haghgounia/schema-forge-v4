# R7.10 Db2 LUW Enablement

## Goal
Add Db2 for Linux, UNIX and Windows (LUW) as an independent SchemaForge platform. Db2 LUW is never treated as a substitute for Db2 for z/OS live acceptance.

## P1 - Core DDL / Mapping / Offline ALTER
Status: CLOSED / PASS.

Verified on 2026-08-26:
- Tests: 20
- Failures: 0
- Errors: 0
- Skipped: 0

Scope:
- `DatabasePlatform.DB2_LUW` with aliases `db2luw`, `db2-luw`, `luw`.
- Historical alias `db2` remains mapped to `DB2_ZOS` for backward compatibility.
- Independent `Db2LuwDialect`, identifier renderer, expression mapper and type mapper.
- NUMBER/DECIMAL fail-closed policy: explicit precision required, maximum precision 31.
- TIMESTAMP precision maximum 12.
- TIMESTAMP WITH TIME ZONE is blocked rather than silently losing the time-zone semantic.
- Core DDL: tables, identity, sequence, PK, UK, FK, CHECK, indexes, comments and grants.
- Db2 LUW table/index tablespace syntax uses `IN <tablespace>`.
- Db2 LUW does not emit the Db2/zOS explicit PK/UK backing-index convention.
- Existing Migration M2 column syntax is enabled with Db2 LUW ALTER forms.
- Batch/run-all recognizes Db2 LUW as a separate artifact platform.

## P2 - SYSCAT JDBC Logical Metadata / Comparison
Status: CLOSED / PASS.

Verified on 2026-08-26:
- Tests: 20
- Failures: 0
- Errors: 0
- Skipped: 0

Scope:
- Independent `Db2LuwMetadataRepository`.
- `JdbcDb2LuwMetadataRepository` backed only by LUW `SYSCAT.*` catalog views.
- `SYSCAT.TABLES` table lookup and schema discovery.
- `SYSCAT.COLUMNS` columns, defaults, identity, generated expressions and comments.
- `SYSCAT.TABCONST` + `SYSCAT.KEYCOLUSE` for PK/UK.
- `SYSCAT.REFERENCES` + `SYSCAT.KEYCOLUSE` for FK column pairing and delete/update rules.
- `SYSCAT.CHECKS` for check expressions.
- `SYSCAT.INDEXES` + `SYSCAT.INDEXCOLUSE` for regular indexes, key direction, INCLUDE columns and expression keys.
- Constraint-enforcing indexes are suppressed from the standalone index list by structural key matching.
- Metadata repository resolver and Spring metadata datasource wiring for `DB2_LUW`.
- SAFE and OPTIMIZED logical datatype comparison.
- Dedicated round-trip marker for LUW `TIMESTAMP(0)` so Oracle DATE mappings are not normalized incorrectly to Db2's default `TIMESTAMP(6)`.

## P3 - Physical Metadata / Physical DDL Contract / Comparison
Status: IMPLEMENTED, awaiting Maven verification.

Scope:
- Table physical metadata from `SYSCAT.TABLES`: `TBSPACE`, `INDEX_TBSPACE`, `LONG_TBSPACE`, `PCTFREE`, `APPEND_MODE`, `VOLATILE`, `TABLEORG`, `COMPRESSION`, `ROWCOMPMODE`.
- Index physical metadata from `SYSCAT.INDEXES`, with tablespace name resolved through `SYSCAT.TABLESPACES`: `PCTFREE`, `MINPCTUSED`, `REVERSE_SCANS`, `COMPRESSION`, `PAGESPLIT`.
- Backing-index physical metadata is attached to PK/UK objects by structural key matching.
- Independent `Db2LuwPhysicalRenderer` for table and index DBA-review candidates.
- Physical comparison properties are isolated under the `DB2_LUW` platform and never reuse the z/OS property contract.
- Db2 catalog code values are mapped to canonical review values without silently normalizing unknown values.

## Non-equivalence rule
`DB2_LUW` and `DB2_ZOS` remain separate dialects, metadata repositories, physical contracts and live acceptance tracks. A LUW PASS never closes a z/OS live gate.
