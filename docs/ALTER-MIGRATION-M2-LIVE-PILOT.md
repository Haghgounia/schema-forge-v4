# ALTER/Migration M2 live pilot

`MySqlMigrationM2LivePilotIT` is an explicit destructive integration pilot for the M2 migration path.
It is disabled during ordinary builds and runs only when MySQL JDBC properties are supplied.

The pilot uses a dedicated disposable `SCHEMAFORGE_*` database and proves both output paths:

1. Full CREATE SQL is generated from the desired model even though the table already exists in live MySQL.
2. A Flyway-compatible ALTER migration is generated by comparing live metadata with the desired model.

The seeded old table intentionally differs from the desired model in column type/nullability/default/add/drop and
PK/FK/UK/CHECK/INDEX definitions. A safe migration is first written with destructive statements commented. The
same plan is then rendered with explicit destructive confirmation, executed on MySQL, re-read through
`JdbcMySqlMetadataRepository`, and diffed again. The test passes only when the residual diff is empty and the
surviving seed row is preserved.

Safety rules:

- `schemaforge.mysql.migration.confirmDestructive=true` is mandatory.
- The pilot database name must start with `SCHEMAFORGE_`.
- The default database is `SCHEMAFORGE_M2_PILOT`.
- Cleanup is enabled by default and drops the dedicated pilot database in `finally`.
- The test never targets the normal application schema by default.

Artifacts are written under `target/mysql-migration-m2-live-pilot/` unless overridden, including:

- `mysql-m2-pilot-create-reference.mysql.sql`
- `SAFE__V...__SF_M2_CHILD_ALTER.sql`
- confirmed `V...__SF_M2_CHILD_ALTER.sql`
- `mysql-m2-live-pilot-summary.txt`
- `residual-diff.txt` only when the post-migration diff is non-empty
M2-R3 closes a MySQL catalog-normalization false positive discovered by this pilot: after a CHECK was replaced successfully, `information_schema.CHECK_CONSTRAINTS.CHECK_CLAUSE` returned MySQL-rendered backticks and UTF literal introducers. The diff engine now treats those catalog decorations as equivalent while preserving the real expression comparison.
