# PostgreSQL PG-P7/P9 — MariaDB parity qualification

## Goal

Bring PostgreSQL to the same end-to-end qualification level already proven for MariaDB, without adding new product features.

Existing PostgreSQL evidence already covers:

- PG-P1 accepted corpus inventory (5,321 scripts)
- PG-P2 historical live execution
- PG-P3 final-state table/column catalog reconciliation
- PG-P4 PK/UK/explicit-index reconciliation
- PG-P5 valid-FK live create/verify/drop qualification
- PG-P6 retained closure evidence
- PostgreSQL M2 live migration with residual diff = 0

The remaining qualification path is therefore:

1. **PG-P7 — dependency-closed integrated cohort**
2. **PG-P8 — persistent FULL deployment** using the existing `PostgreSqlDirectoryExecutionTest`
3. **PG-P9 — read-only catalog convergence** using `JdbcPostgreSqlMetadataRepository` + `SchemaDiffEngine`
4. External DBA-created table/schema audit qualification after P9 convergence

## PG-P7 contract

Inputs are the persisted canonical JSON corpus plus the existing DBMS-neutral selection manifest generated by `CanonicalJsonSelectionManifestIT`.

Rules:

- Only `AUTO_SELECTED_UNIQUE` and `AUTO_SELECTED_EXACT_DUPLICATE` rows are accepted.
- No historical winner is guessed.
- No FK, datatype, PK/UK, or table definition is rewritten.
- Tables that cannot render/sanity-check locally for PostgreSQL are excluded with evidence.
- Remaining physical-FK blockers are resolved only by transitively excluding the FK owner table.
- The final cohort must be `ForeignKeyAnalyzer.deployable=true` before integrated SQL is emitted.

Outputs include the selected closed cohort, exclusions, closure iterations, contract mismatches, summary, and one integrated PostgreSQL SQL script.

## PG-P8 contract

Use `PostgreSqlDirectoryExecutionTest` with `postgresql.sql.executionMode=FULL` and `dropBeforeCreate=true` against the disposable PostgreSQL qualification schema. The integrated SQL is executed as one persistent deployment; FK statements are not skipped.

## PG-P9 contract

PG-P9 is read-only. It reloads the exact P7 selected canonical snapshots and compares each expected table to live PostgreSQL metadata using the production `JdbcPostgreSqlMetadataRepository` and existing `SchemaDiffEngine`.

Qualification target:

- missing expected tables = 0
- contract mismatches = 0
- residual column changes = 0
- residual object changes = 0
- cohort converged = true

Extra unrelated tables in the target schema are reported separately and are non-fatal unless explicitly enabled.

## FK policy

Per project policy, malformed historical/documentation-only FK declarations are not DBMS capability blockers. PostgreSQL FK capability is already proven by PG-P5 for structurally valid FKs. P7/P8/P9 only require the selected integrated cohort itself to be physically deployable and round-trip clean.
