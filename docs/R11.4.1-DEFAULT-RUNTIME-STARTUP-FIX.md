# R11.4.1 Default Runtime Startup Fix

## Problem

The default `application.yml` enabled Db2 LUW metadata while IBM JCC was only
available through the opt-in Maven profile `db2luw-live`. As a result,
`mvn spring-boot:run` failed during ApplicationContext creation with:

`ClassNotFoundException: com.ibm.db2.jcc.DB2Driver`

This contradicted the POM contract that normal builds/runtime do not require
IBM JCC.

## Fix

Db2 LUW metadata is now disabled by default:

`schemaforge.metadata.db2luw.enabled=${SCHEMAFORGE_METADATA_DB2LUW_ENABLED:false}`

Normal runtime therefore starts without JCC. Live Db2 LUW metadata remains
explicit and opt-in.

## Live Db2 LUW runtime

Use both the Maven profile and the runtime enable switch:

```bat
set "SCHEMAFORGE_METADATA_DB2LUW_ENABLED=true"
mvnw.cmd -Pdb2luw-live spring-boot:run
```

## Regression guard

`DefaultRuntimeStartupContractTest` boots the Spring context without any IBM
JCC dependency and fails if Db2 LUW becomes implicitly enabled again.

No DDL, canonical, dialect, migration, artifact, API, or ZIP production logic
is changed by this patch.
