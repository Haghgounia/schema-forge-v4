# EA IAM XMI 2.1 import correction — 2026-10-31

## Scope

`IAM-TARGET-R0.9.xmi` uses core `uml:Class` + `ownedAttribute` and EA `xmi:Extension/attribute` physical properties. Its PK, FK, UK and CHECK rules are expressed by `ownedRule/specification/body` rather than operation stereotypes. Foreign keys also have `xmi:Extension/connectors/connector` metadata, including `source`, `target`, a connector name and documented child -> parent column lists.

The older importer required a literal `column` stereotype; it therefore returned `EA table REF_DOMAIN_TYPES does not contain any column elements` even though the source has seven attributes.

## Implementation

- Physical UML `ownedAttribute` is treated as a column only if the EA extension provides an explicit physical type. Missing type is an error, not an inferred `VARCHAR2`.
- SQL-backed `ownedRule` supports PK, UK/UQ, FK and CHECK. Unknown or malformed rule bodies fail closed.
- FK connector identity, endpoint names, ownedRule columns, documented child -> parent mapping and referenced PK/UK definition must agree. A missing or ambiguous link fails closed instead of silently dropping the FK.
- The importer requires preservation of the declared PK, UK, FK and CHECK counts per table.
- XMI 2.1 columns with explicit integer PK `SCHEMA.SEQUENCE.NEXTVAL` defaults carry a logical identity marker while retaining the original default. The existing dialect logic then emits MySQL/MariaDB `AUTO_INCREMENT` rather than illegal MySQL sequence defaults. Generic PK-to-identity inference remains disabled by default, and earlier XMI 1.x formats retain their behavior.
- Constraint names are still subjected to the existing SpecificationNormalizer naming policy. Very long or truncated native connector identifiers are not relied upon as exact physical DBMS names.

## Caveats / separate gates

- The source labels some model tables `R0.6_REVIEW_ONLY` / `Review`. Import success does not indicate authorization to deploy that design.
- The XMI includes 21 explicit sequence NEXTVAL defaults but no corresponding CREATE SEQUENCE model objects. Oracle/other source-preserving dialect deployments may need pre-existing sequences or a separately reviewed provisioning plan. No sequence start/increment has been invented here.
- Timezone-preserving semantics are not guaranteed for cross-DBMS MySQL timestamp fallback: consult generated warning comments before deployment.
- No independent index definitions are present as operation stereotypes in this XMI. The importer does not invent missing physical indexes.
- No Maven/JUnit runtime or live DBMS acceptance was executed in this offline container. Standalone Java 21 compilation and six test methods with temporary local JUnit signatures succeeded; the real IAM corpus and seven dialects were used.
