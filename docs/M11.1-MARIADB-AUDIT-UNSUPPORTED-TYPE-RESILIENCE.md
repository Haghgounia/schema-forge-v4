# M11.1 - MariaDB external audit unsupported-type resilience

## Problem

A live MariaDB schema can contain valid native datatypes that SchemaForge intentionally does not map losslessly for DDL generation. `MEDIUMINT` exposed this contract: `DatatypeCompatibilityAnalyzer` correctly reports it as unsupported, but `MetadataComparisonValidator` attempted to render the same live datatype through `MariaDbDialect.sqlType()` first and aborted the whole audit.

## Resolution

Metadata comparison no longer treats a target-dialect mapping refusal as a control-flow failure. It falls back to the live/native canonical type signature for metadata convention comparison and allows the dedicated datatype compatibility analyzer to emit the unsupported-type finding.

This preserves the separation between:

- **Auditability:** read and validate any existing native database object without mutation or crash.
- **DDL portability:** fail closed when SchemaForge cannot generate a lossless target mapping.

No unsupported datatype mapping was added and no lossy conversion is introduced.
