# SchemaForge V4 - Artifact Naming and Layout Contract

Status: **C5.3 COMPLETE / USER-VERIFIED / OFFICIAL C5 CONTRACT**  
Contract scope: consumer-visible artifact paths and filenames  
Baseline input: `SCHEMAFORGE-V4-CONSOLIDATED-BASELINE-20260822-C4.3`  
Frozen source fingerprint: `8566f2218d2737b0c571452e465760908a8c527c05fa0b2bc0b6d8f1a04bad37`

## 1. Purpose

C5 consolidates endpoint-specific artifact naming/layout into one artifact-first contract. It changes where generated files appear and normalizes non-Flyway filenames, but does not change parser behavior, canonical semantics, DDL/CRUD SQL semantics, metadata recovery, physical DDL, or migration diff/safety rules.

`ArtifactNamingPolicy` is the production naming authority for non-Flyway artifact identities. `FlywayMigrationNamer` remains authoritative for Flyway migration filenames; C5 controls only their canonical package directory.

## 2. Canonical layout

```text
ddl/<platform>/
migration/<platform>/
crud/<platform>/
model/
comparison/<platform>/
diagram/mermaid/tables/
diagram/mermaid/batch/
diagram/graphviz/tables/
diagram/graphviz/batch/
scripts/<platform>/
reports/
manifest.json                    # currently EA; common manifest semantics are C6
```

The same layout applies to Word, Legacy Word, ZIP Batch, and EA packages. ZIP Batch no longer reclassifies a document artifact from its filename suffix; it preserves the canonical relative path generated by the document pipeline.

## 3. Naming grammar

### DDL

```text
ddl/<platform>/<logical>_<generationTimestamp>.<platform>.sql
```

### Flyway migration

```text
migration/<platform>/V...__<description>.sql
```

The filename grammar remains owned by the Flyway subsystem and is not rewritten by C5.

### CRUD

```text
crud/oracle/<schema.table>_<generationTimestamp>.oracle.crud-package.sql
crud/sqlserver/<schema.table>_<generationTimestamp>.sqlserver.crud-procedures.sql
```

The existing CRUD semantic suffixes are preserved.

### Canonical model

```text
model/<source>_<generationTimestamp>.schema.json
```

This deliberately reuses the existing `*.schema.json` canonical snapshot convention.

### Comparison workbook

```text
comparison/<platform>/<schema.table>_<generationTimestamp>.<platform>.compare.xlsx
```

### Per-source diagrams

```text
diagram/mermaid/tables/<source>_<generationTimestamp>.er.mmd
diagram/mermaid/tables/<source>_<generationTimestamp>.conceptual-erd.mmd
diagram/graphviz/tables/<source>_<generationTimestamp>.er.dot
diagram/graphviz/tables/<source>_<generationTimestamp>.conceptual-erd.dot
```

### Batch diagrams/reports

Existing semantic batch filenames are preserved under the common `diagram/` root. Examples:

```text
diagram/mermaid/batch/schema-er.mmd
diagram/mermaid/batch/schema-conceptual-erd.mmd
diagram/mermaid/batch/schema-dependency.mmd
diagram/mermaid/batch/issues.csv
diagram/mermaid/batch/summary.txt

diagram/graphviz/batch/schema-conceptual-erd.dot
diagram/graphviz/batch/schema-dependency.dot
diagram/graphviz/batch/schema-clustered.dot
diagram/graphviz/batch/schema-compact.dot
diagram/graphviz/batch/schema-overview.dot
diagram/graphviz/batch/issues.csv
diagram/graphviz/batch/summary.txt
```

### EA run-all scripts

```text
scripts/<platform>/<source>_<generationTimestamp>.<platform>.run-all.sql
```

The script references the canonical DDL location using relative paths, for example SQL Server `:r ../../ddl/sqlserver/...`.

### Reports

```text
reports/<source>_<generationTimestamp>.metadata-crud-summary.csv
reports/batch-generation-summary.csv
reports/batch-generation-errors.log
```

## 4. Request timestamp rule

Every top-level generation request owns one `generationId` and one `generationTimestamp`. Child/isolated contexts inherit both. Therefore all normal timestamped artifacts in one Word/Legacy/EA request share one timestamp, and every document artifact inside one ZIP Batch shares the batch request timestamp.

Flyway versions remain independently monotonic and are not replaced by the request timestamp.

## 5. Collision rule

Collision resolution is evaluated on the final canonical relative path.

Normal path:

```text
<logical>_<timestamp>...
```

Second colliding source:

```text
<logical>__sf_<10-hex-stable-hash>_<timestamp>...
```

Properties:

- the first reservation keeps the canonical path;
- the suffix is deterministic from stable source identity plus canonical target identity;
- comparisons are case-insensitive to prevent archive collisions across case-insensitive consumers;
- no random UUID is exposed in consumer-visible names;
- Flyway path collisions fail rather than silently renaming a versioned migration.

`CollisionSafeScriptTargetAllocator` is retained as a backward-compatible adapter but delegates to the C5 central naming/collision policy.

## 6. Standalone generation

Standalone Oracle/SQL Server CRUD retains its existing attachment filename grammar, but the name is now obtained through `ArtifactNamingPolicy`.

Standalone canonical-JSON Mermaid keeps its deterministic selector grammar (for example `BIM_PROVINCES__dependency-table-with-dependencies-depth-2.mmd`); ownership of that grammar moved to `ArtifactNamingPolicy` without a consumer-visible rename.

The offline `SchemaGenerationService` now follows the same canonical `ddl/<platform>/` and `model/` layout instead of maintaining a second root-level naming convention.

## 7. Explicitly unchanged semantics

C5.3 does not modify:

- Word/Legacy/EA parser algorithms;
- canonical domain model semantics;
- datatype mapping;
- DDL generators or SQL contents;
- physical DDL rendering;
- metadata repositories/recovery;
- migration diff/safety/rendering semantics;
- Flyway filename grammar;
- CRUD SQL generators;
- REST endpoint URLs or HTTP response bodies;
- Artifact Contract V1 field semantics;
- common manifest schema (C6).

Source-tree comparison against C4.3 confirms the `generation`, `dialect`, `specification`, `metadata`, `migration`, and `domain` packages are byte-unchanged.

### C5.3 regression repair R1

The first full C5.3 regression executed `492` tests and exposed one stale test assumption in `DirectoryDualDatabaseGenerationRunnerTest`: the test inspected only direct children of the output directory even though C5 now places generated DDL under `ddl/oracle/` and `ddl/postgresql/`. The production runner had generated all expected scripts; only the regression assertion was obsolete. R1 updates that test to recursively enumerate regular files and to assert the canonical C5 DDL roots. No production Java source or generated artifact semantics changed.
